# DSP-7. Реестр заявок и переходы состояний

**Автор:** Марина Кольцова, тимлид · **Неделя:** 7

До сих пор «Диспетчер» только читал файл. Теперь диспетчер будет менять заявки: назначать мастера, отмечать выполнение, закрывать. И здесь заказчик жёсток: закрыть можно только выполненную [Б2], задним числом ничего не менять [А8]. Значит, правила переходов должны жить в одном месте, и обойти их нельзя. Это работа для класса.

`Request` остаётся структурой: это запись строки файла, её поля ничем не связаны между собой. А **все заявки файла вместе** — объект с инвариантами: номера не повторяются, состояние меняется только по правилам. Это `class Registry`.

## Что сделать

### 1. Переходы состояний

```text
          assign              complete             close
 новая ─────────────▶ назначена ────────▶ выполнена ──────▶ закрыта
   │                   │    ▲
   │                   └────┘ assign (другой мастер)
   │ cancel            │ cancel
   └──────────▶ отменена ◀┘
```

Любой другой переход — `TransitionError`.

### 2. `include/dispatch/registry.hpp`

```cpp
namespace dispatch {

class NotFound : public std::out_of_range { using std::out_of_range::out_of_range; };
class TransitionError : public std::logic_error { using std::logic_error::logic_error; };

class Registry {
public:
    Registry() = default;
    explicit Registry(std::vector<Request> requests);          // повтор номера — std::invalid_argument
    static Registry load(const std::string& path, std::ostream& errors);   // через load_requests

    void save(const std::string& path) const;                   // см. ниже
    const std::vector<Request>& all() const;
    const Request* find(int id) const;
    std::size_t size() const;

    void assign(int id, const std::string& master);   // новая, назначена -> назначена
    void complete(int id, const std::string& when);   // назначена -> выполнена, done = when
    void close(int id);                               // выполнена -> закрыта
    void cancel(int id);                              // новая, назначена -> отменена

private:
    Request& get(int id);                             // нет заявки — NotFound
    std::vector<Request> requests_;
};

}
```

Тексты ошибок:

| Ситуация | Исключение | Текст |
|---|---|---|
| нет заявки | `NotFound` | `заявка 17 не найдена` |
| недопустимый переход | `TransitionError` | `заявка 17: нельзя закрыть заявку в состоянии «новая»` (действия: `назначить`, `отметить выполненной`, `закрыть`, `отменить`) |
| пустой мастер | `std::invalid_argument` | `мастер: пусто` |
| `when` — не дата `ГГГГ-ММ-ДД ЧЧ:ММ` | `std::invalid_argument` | `выполнена: не дата «…»` |
| `when` раньше создания заявки | `std::invalid_argument` | `выполнена раньше создания` |

Проверки — в таком порядке: заявка существует; мастер не пустой (для `assign`); переход разрешён; дата правильная и не раньше создания (для `complete`). Если метод бросил исключение, реестр не изменился.

### 3. Сохранение

`save` пишет файл, который открывается в Excel двойным щелчком [Б7]: в начале BOM (`EF BB BF`), заголовок, по заявке в строке в порядке реестра, каждая строка — с `\r\n`. Поля — через `;`, описание — последним, как есть.

Сохранение **атомарное**: сначала весь файл пишется во временный `путь.tmp`, потом `std::filesystem::rename` заменяет им старый. Если программа упадёт посреди записи, старый файл останется целым — вспомните обрывок строки из недели 5. Не записалось — `FileError`.

### 4. Команды

```text
$ dispatch assign requests.csv 17 Петров
заявка 17: назначена, мастер Петров
$ dispatch done requests.csv 17 2026-10-05 09:02
заявка 17: выполнена 2026-10-05 09:02
$ dispatch close requests.csv 17
заявка 17: закрыта
$ dispatch cancel requests.csv 18
заявка 18: отменена
```

- Команда загружает реестр, выполняет действие и сохраняет файл. Ошибка — текст исключения в stderr, код 1, файл не меняется.
- Если в файле есть ошибочные строки, менять его нельзя: сохранение молча выбросило бы их. Тогда — ошибки строк в stderr, как обычно, и `в файле есть ошибки — сначала исправьте их (dispatch check)`, код 1.
- `done`: всё после номера, соединённое пробелом, — дата выполнения: `2026-10-05 09:02` — это два аргумента, но одна дата.
