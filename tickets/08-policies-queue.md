# DSP-8. Кого послать: правила назначения и очередь

**Автор:** Марина Кольцова, тимлид · **Неделя:** 8

Сергей Петрович описал, как выбирать мастера [Б4], — и добавил: «пока так, а там посмотрим». Значит, правил будет несколько, и программа не должна переписываться при каждом новом. Делаем правило объектом с общим интерфейсом: `suggest` не знает, какое правило ему дали, — он просто спрашивает. И вторая просьба: аварийные заявки — первыми [Б9].

## Что сделать

### 1. Мастера — `include/dispatch/masters.hpp`

Файл мастеров — CSV в UTF-8, `;`, первая строка `мастер;специальность`, дальше — фамилия и специальность: вид работ из списка или `универсал`.

```cpp
namespace dispatch {

struct Master {
    std::string name;
    std::string specialty;   // вид работ или «универсал»
};

std::vector<Master> read_masters(std::istream& in);          // ошибки — ParseError
std::vector<Master> load_masters(const std::string& path);   // + FileError «не открыть файл: …»

int workload(const Registry& registry, const std::string& master);   // заявок «назначена» у мастера

class AssignPolicy {
public:
    virtual ~AssignPolicy() = default;
    // Кого назначить на заявку r; nullptr — некого. Указатель — на элемент masters.
    virtual const Master* choose(const Request& r, const std::vector<Master>& masters,
                                 const Registry& registry) const = 0;
};

class SpecialtyPolicy : public AssignPolicy { … };    // правило заказчика [Б4]
class LeastLoadedPolicy : public AssignPolicy { … };  // просто наименее загруженный

std::unique_ptr<AssignPolicy> make_policy(const std::string& name);   // "specialty", "least"; иначе std::invalid_argument
}
```

Ошибки файла мастеров — `ParseError`, весь файл отвергается (мастеров мало, ошибка в нём — всегда ошибка): `мастера: первая строка — не заголовок`, `мастера, строка 4: пустая фамилия`, `мастера, строка 5: неизвестная специальность «газовщик»`, `мастера, строка 6: мастер «Петров» уже есть`. BOM и `\r` — как у файла заявок.

**Правило заказчика** (`SpecialtyPolicy`). «Свободный» — у кого меньше трёх заявок «назначена».

1. Среди свободных мастеров со специальностью, равной виду работ заявки, — наименее загруженный.
2. Нет таких — среди свободных универсалов — наименее загруженный.
3. Нет и таких — среди всех мастеров этой специальности и универсалов — наименее загруженный.
4. Никого нет — `nullptr`.

При равной загрузке — фамилия меньше (сравнение строк `<`). `LeastLoadedPolicy` — наименее загруженный из всех мастеров, при равенстве — тоже по фамилии.

### 3. Команды

```text
$ dispatch queue requests.csv
№17 | аварийная | 2026-09-01 03:28 | сантехника | назначена | Лесная 12, кв. 45
№4 | обычная | 2026-09-01 00:40 | лифт | новая | Мира 3, кв. 7
…
в очереди: 93

$ dispatch suggest requests.csv masters.csv 4
заявка 4 (лифт): Морозов, в работе 1
$ dispatch suggest requests.csv masters.csv 4 least
заявка 4 (лифт): Кузнецов, в работе 0
```

- `suggest ФАЙЛ МАСТЕРА НОМЕР [ПРАВИЛО]` — правило по умолчанию `specialty`. Файл заявок не меняется: назначает диспетчер командой `assign`.
- Заявка не открытая → `заявка 3: нельзя назначить заявку в состоянии «закрыта»`; некого — `заявка 4: некого назначить`; нет заявки — `заявка 99 не найдена`; неизвестное правило — `неизвестное правило «x»`; ошибки файла мастеров — текст `ParseError`. Всё в stderr, код 1.
- Ошибки строк файла заявок — в stderr, как обычно, и работа продолжается: `suggest` и `queue` ничего не записывают.
