# DSP-11. Новая заявка из окна

**Автор:** Марина Кольцова, тимлид · **Неделя:** 11

Главное, что делает диспетчер, — принимает звонок и заводит заявку [А2]. Регистрация — не дольше минуты (НФ из ТЗ): форма с понятными полями, неправильное нельзя ввести, номер и время программа ставит сама. Правила заявки — в библиотеке: окно только собирает поля и передаёт их реестру.

## Что сделать

### 1. `Registry::add` в `dispatch_core`

```cpp
// Новая заявка: номер — на единицу больше наибольшего (1 для пустого реестра), created = now,
// состояние «новая», мастер и дата выполнения пустые. Поля черновика проверяются, как при чтении
// файла (тексты ошибок DSP-3), плюс: описание не пустое — «описание: пусто», без перевода строки —
// «описание: перевод строки». Ошибка — ParseError, реестр не меняется. Возвращает номер.
int add(Request draft, const std::string& now);
```

Подсказка: проверку полей не нужно писать второй раз — у вас есть `format_request` и `parse_request`.

### 3. Окно

- `MainWindow` хранит реестр и путь открытого файла.
- Меню «Заявки» → действие «Новая заявка» (`QAction` с именем объекта `newRequestAction`, клавиши Ctrl+N): диалог, по OK — `add_request(dialog.draft(), текущее время)`.
- Проверяемая часть — метод без диалога:

```cpp
// Добавить заявку в открытый файл и сохранить его. false — не получилось, причина — в summaryLabel.
bool add_request(const dispatch::Request& draft, const QString& now);
```

  После успеха таблица и итог обновлены, файл сохранён (`Registry::save`). Ошибки — текст `ParseError` или `FileError` в `summaryLabel`. Файл с ошибочными строками не меняется, как в DSP-7: `в файле есть ошибки — сначала исправьте их (dispatch check)`. Файл не открыт — `файл не открыт`.
- Текущее время — `QDateTime::currentDateTime().toString("yyyy-MM-dd HH:mm")`.
