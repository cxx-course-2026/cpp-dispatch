# DSP-12. Модель заявок, фильтры и график

**Автор:** Марина Кольцова, тимлид · **Неделя:** 12

Диспетчеру нужно видеть не все четыреста заявок, а «лифты, которые ещё не сделаны». Директору — график по дням [А6, Б5]. А нам пора перестать держать вторую копию заявок в ячейках `QTableWidget`: данные живут в `Registry`, таблице достаточно модели, которая показывает реестр как есть.

## Что сделать

### 1. `per_day` в `dispatch_core`

```cpp
// include/dispatch/stats.hpp
// Число заявок по дню создания: от самого раннего дня до самого позднего подряд, дни без заявок — с нулём.
std::vector<std::pair<std::string, int>> per_day(const Registry& registry);   // {"2026-09-01", 126}, …
```

### 2. Модель и фильтр — `src/gui/`

- `RequestModel : QAbstractTableModel` над реестром: те же семь столбцов, порядок строк и фон аварийных, что в DSP-10 (`Qt::DisplayRole`, `Qt::BackgroundRole`). Новый реестр — `beginResetModel()`/`endResetModel()`.
- `RequestFilter : QSortFilterProxyModel` — фильтр по виду работ и по состоянию (`filterAcceptsRow`).
- Центральный виджет — `QTableView` с именем `requestsTable`, его модель — фильтр поверх `RequestModel`. `QTableWidget` больше не нужен.

### 3. Окно

- Панель инструментов с двумя списками:
  - `kindFilter` — `все виды`, затем шесть видов работ;
  - `stateFilter` — `все`, `открытые` (новая и назначена), затем пять состояний.
- Надпись `shownLabel` в строке состояния рядом с итогом: `показано: 35` — сколько строк видно после фильтров.
- Меню «Файл» → «Открыть…» (`openAction`, Ctrl+O) — `QFileDialog`, потом `open_file`.
- Внизу — `QDockWidget` с графиком: виджет `DayChart` с именем объекта `dayChart` рисует на `QPainter` столбики `per_day` (подписи дней — по желанию). Метод `std::vector<std::pair<std::string, int>> days() const` — что он сейчас показывает. График обновляется при открытии файла и добавлении заявки.
- `summaryLabel` и всё из DSP-10 и DSP-11 работает как раньше.
