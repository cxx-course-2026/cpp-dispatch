# DSP-6. Релиз 0.1

**Автор:** Марина Кольцова, тимлид · **Неделя:** 6

Первая версия уходит заказчику: Сергей Петрович хотел попробовать программу на реальных данных до 15 ноября [Б8]. Первым делом он сделает то, что делает любой заказчик, — откроет свой файл, выгруженный вручную из Excel, и посмотрит, что программа о нём думает. Поэтому в релиз входит проверка файла, и к программе — документы, без которых её не установить и не понять.

## Что сделать

### 1. `dispatch check ФАЙЛ`

Проверка файла заявок целиком, без других действий:

```text
$ dispatch check data/requests.csv
строка 7: полей 5, нужно 12
строка 9: неизвестный вид работ «газ»
строк: 412, заявок: 410, ошибок: 2
```

- Ошибки строк печатаются в **stdout** (это и есть результат команды), по одной, в порядке строк файла, в том же виде, что в DSP-3.
- Последняя строка — итог: `строк` — сколько строк заявок в файле, не считая заголовка и пустых; `заявок` — сколько прошли проверку; `ошибок` — сколько не прошли.
- Код возврата: 0 — ошибок нет, 1 — есть хотя бы одна. Так команду можно вставить в скрипт: `dispatch check файл && …`.
- Ошибки файла (не открывается, не тот заголовок) — в stderr, код 2: это уже не «в файле ошибки», а «проверить нечего».

### 2. Журнал изменений — `CHANGELOG.md`

Формат [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/): раздел `## [0.1.0] - ГГГГ-ММ-ДД` с подразделом `### Добавлено` и списком того, что умеет версия: команды, формат файла, проверки. Над ним — пустой раздел `## [Unreleased]` для будущих изменений.

### 3. Руководство оператора — `docs/USER_GUIDE.md`

Для диспетчера, а не для программиста. Разделы по ГОСТ 19.505-79 «Руководство оператора»:

- `## 1. Назначение программы` — для чего и кому;
- `## 2. Условия выполнения программы` — компьютер, система, где лежит файл заявок;
- `## 3. Выполнение программы` — каждая команда (`count`, `show`, `report`, `find`, `check`) с примером вызова и вывода;
- `## 4. Сообщения оператору` — все сообщения об ошибках из DSP-3 и этого тикета: что значит и что делать.

### 4. Релизная сборка и тег

- Проект собирается в конфигурации Release без санитайзеров и без единого предупреждения: `cmake -S . -B build-release -DCMAKE_BUILD_TYPE=Release -DSAN=OFF && cmake --build build-release`. Оптимизатор находит предупреждения, которых нет в Debug, — например, о переменных, которые могут остаться неинициализированными.
- Версия в `CMakeLists.txt` — `0.1.0`.
- После слияния PR — аннотированный тег на коммите в `main`: `git tag -a v0.1.0 -m "Диспетчер 0.1.0"` и `git push origin v0.1.0`.

## Критерии готовности

- `make check-chk6` зелёная в PR; `make check-rel6` станет зелёной после тега `v0.1.0` (проверки запускаются и на push тега). Проверки прошлых тикетов — зелёные.
- PR `dsp-6` в `main`, после слияния — тег `v0.1.0`. В описании PR — как вы проверили руководство: дали ли его прочитать человеку, который не видел код, и что он не понял.
