# «Диспетчер» — программа для диспетчерской управляющей компании

Сквозной проект курса «C++ и Qt». Вы пишете его с нуля, тикет за тикетом: от ТЗ по письму заказчика до настольного приложения на Qt, в котором диспетчер заводит заявки жильцов, назначает мастеров, следит за сроками и выгружает отчёт с графиком.

## Легенда

Тимлид — Марина Кольцова, она пишет тикеты и принимает PR. Требования приходят письмами от главного инженера УК — Сергея Петровича Гончаренко.

## Правила проекта

1. **Сначала ТЗ, потом код.** Каждая функция программы следует из требования ТЗ, каждое требование — из письма заказчика.
2. **Только стандартная библиотека C++**, пока тикет не разрешит другое. С недели 10 — Qt 6.
3. **Сборка без предупреждений.** `cmake/flags.cmake` превращает любое предупреждение в ошибку и включает санитайзеры — не выключайте их.
4. **Каждый тикет — pull request** в `main` с зелёными проверками. В описании PR — что сделано, как проверено и на что обратить внимание ревьюеру.

## Что где

```text
CMakeLists.txt     описание сборки — пишете вы, начиная с DSP-1
cmake/flags.cmake  настройки компилятора курса: подключите, но не меняйте
src/               ваш код; с DSP-5 — ещё include/dispatch/ (публичные заголовки библиотеки)
tests/             ваши тесты (с DSP-5)
docs/              ваши документы: ТЗ, руководство, описание программы
letters/           письма заказчика
tickets/           тикеты — по одному на неделю
checks/            проверки тикетов: читайте, но не меняйте
```

## Рабочий цикл

```bash
make                  # собрать в build/ (или откройте каталог в CLion, VS, VS Code, Qt Creator)
./build/dispatch --help
make check            # проверки всех тикетов
make check-tz1        # одна проверка
make update           # новые тикеты, письма и проверки из шаблона курса
```

Проверки собирают проект заново в `build-check/` из `checks/CMakeLists.txt`: он подключает ваш проект подкаталогом и добавляет к нему модульные проверки тикетов. Поэтому в вашем `CMakeLists.txt` пути пишите от `${CMAKE_CURRENT_SOURCE_DIR}`, а не от корня сборки, и не подключайте `checks/` сами.

Проверки гоняют все тикеты сразу. Новые тикеты появляются каждую неделю: выполните `make update` — он заберёт из шаблона курса новые `tickets/`, `letters/` и `checks/`, не трогая ваш код и документы, — и закоммитьте обновление отдельным коммитом.
